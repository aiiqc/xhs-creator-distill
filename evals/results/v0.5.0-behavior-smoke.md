## 同期确定性验证

- 本地 Python 3.12.14 与 3.14.3：适配器各 `37/37 PASS`，含两套五项黄金输出逐字节回归；golden 文件未改。
- 仓库 validator 与其 29 项正反向检查：`PASS`；Ruby 安全 YAML/frontmatter 检查、Python 编译与 diff 空白检查：`PASS`。
- 修复前新增 parser-limit 用例在 Python 3.12.14 的输入 JSON/字段映射 × 超长整数/深度嵌套四条分支失败，非 UTF-8 locale 模拟的两个帮助别名解码失败；修复后通过。未关闭解析器限制。
- Skill 创建工具附带的 `quick_validate.py`：`NOT RUN`，两个本地 Python 都缺少 PyYAML，未安装新依赖；仓库 validator 与 Ruby YAML 是本轮实际执行的静态验证，不冒称该工具已通过。
- GitHub Ubuntu/Python 3.10、macOS/Windows CI 是单独的发布门槛，以本版 Release 所链接运行结果为准，不由本地通过推定。

## 限制与历史关系

- 只测试中文语义交付；五语 README 经过同步检查，但本轮未重跑五种语言的完整模型行为。
- 未测试宿主自动发现、安装升级、真实账号读取、真实导出兼容或外部使用量。
- 账号模式的两套适配器回归不等于账号模式的完整语义 E2E；本轮语义场景聚焦 QUICK_SET 和输出形态变化。
- 八月的旧烟雾记录保持历史原样，不作为本轮证据。此次正向测试使用完整独立短笔记，摘要单独作为负例。
- 未留存完整会话、内部推理或工具转录；以上仅保留必要合成输入来源、用户式请求、可观察片段和判定。
