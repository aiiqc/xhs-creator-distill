# 蒸馏报告输出协议

完整报告必须遵循本协议。每次都先显示输入模式和实际覆盖，再给结论。

## 目录

1. 状态与模式
2. 证据编号
3. 置信度
4. 必需结构
5. 分模式输入审计
6. 表格字段
7. 质量门槛

## 状态与模式

只使用以下状态：

- `PASS`：实际取得 3–8 篇同一创作者的有效独立完整内容，可以按已声明的范围完成报告。
- `HOLD`：样本、归属、访问、解析、安全或资源问题阻止完整蒸馏；必须列出准确原因和最小补救动作。

只使用以下模式代码：

| 模式 | 含义 |
| --- | --- |
| `QUICK_SET` | 用户直接提供 3–8 篇代表笔记 |
| `PUBLIC_SAMPLE` | 对用户指定的公开账号做有界盘点和取样 |
| `ACCOUNT_PACKAGE` | 对用户提供的导出、文件或资料包做全包盘点和取样 |

不使用“基本通过”“大概可用”等模糊状态。`PASS` 表示对覆盖声明中的范围可交付，不等于公开账号已全量覆盖。

## 证据编号

### 深析证据 `Nxx`

- `N01`–`N08` 是完整阅读和深度分析的独立样本。
- 内容机制、表达、结构、动机替代解释和原创适配必须优先使用 `Nxx` 证据。
- 完全重复、高度近似或同稿多发只计一个独立 `Nxx` 证据。

### 盘点来源 `Sxxx`

- `S001`、`S002`… 表示 `PUBLIC_SAMPLE` 或 `ACCOUNT_PACKAGE` 中盘点到的可识别条目。
- 账号模式必须显示 `Nxx → Sxxx` 映射。
- 只有标题、日期或互动数据的 `Sxxx` 不能单独支持表达或结构结论。

### 聚合证据 `Axx`

- `A01`、`A02`… 是从已成功解析的盘点范围计算得到的客观计数或分类。
- 每条必须记录分子、分母、使用字段、时间范围、未解析项和分类口径。
- `Axx` 可支持“已解析条目中的主题分布”，不能单独支持作者人格、动机、表达 DNA 或平台因果。

## 置信度

### 证据类型

- `观察`：已取得材料中直接可见，用简短转述和 ID 定位。
- `推断`：由多个观察归纳，必须说明替代解释或限制。
- `未知`：当前材料不能支持；不得补造。

### 内容机制门槛

设深析集中有效独立样本数为 `V`：

| 置信度 | 门槛 |
| --- | --- |
| 高 | 至少 `max(3, ceil(V / 2))` 个独立 `Nxx` 支持，且无未解释的实质反例 |
| 中 | 至少 2 个独立 `Nxx` 支持；存在的冲突已被限定为条件或例外 |
| 低 | 仅 1 个 `Nxx` 支持、依赖较强推断、存在冲突，或材料信息有限 |

任何中、高置信度的内容机制都必须列出全部支持 `Nxx`。低置信度不能写成确定事实。

主观置信度只有三个语义值，并按输出语言使用以下固定标签：

| 输出语言 | 高 | 中 | 低 |
| --- | --- | --- | --- |
| 简体中文 / 繁体中文 / 日文 | `高` | `中` | `低` |
| English | `High` | `Medium` | `Low` |
| 한국어 | `높음` | `보통` | `낮음` |

不得创造“中高”、“较高”、`Medium-high`、星级或百分比等额外等级。客观覆盖率可以使用百分比，但必须与置信度分开展示。输出非简体中文时，报告标题、字段名和类型标签也应跟随用户语言；模式代码和证据 ID 保持不变。

## 必需结构

### 1. 标题、状态与覆盖

```markdown
# 创作者内容操作系统蒸馏报告

状态：PASS / HOLD
输入模式：QUICK_SET / PUBLIC_SAMPLE / ACCOUNT_PACKAGE
覆盖声明：[实际盘点数、完整文本数、深析数和停止原因]
分析范围：仅基于本次已成功读取的材料
```

以上四项必须出现在任何摘要或核心结论之前。

### 2. 输入审计

使用下节对应模式的字段。不得隐藏未解析、未覆盖或已截断范围。

若为 `HOLD`，输入审计后只补充“阻塞原因、需要用户补充或更改的内容、可做的有限观察”，不继续输出完整五层结论。

### 3. 执行摘要

在 `PASS` 时列出 3–6 个最重要模式：

| 模式 | 类型 | 证据 | 置信度 | 一句话限制 |
| --- | --- | --- | --- | --- |
| 可执行的机制描述 | 观察 / 推断 | Nxx, Nxx；可选 Axx | 高 / 中 / 低 | 适用条件或未知项 |

### 4. 五层内容操作系统

依序使用以下标题：

```markdown
## 一、定位层
## 二、选题层
## 三、结构层
## 四、表达层
## 五、运营层
```

每层使用结论表：

| 字段 | 内容 |
| --- | --- |
| 观察 | 材料直接呈现的模式 |
| 可迁移规则 | 情境、动作、作用 |
| 适用条件 | 规则成立的主题、受众或资源条件 |
| 反例或限制 | 冲突样本、替代解释、缺失信息 |
| 证据 | 全部支持和反对的 Nxx；账号模式可补 Axx |
| 类型与置信度 | 观察 / 推断；高 / 中 / 低 |

证据不足时明确写“未知”，不为了填满五层而制造结论。

### 5. 模式边界

分开列出：

- 稳定模式；
- 条件模式；
- 单次实验或离群项；
- 相互冲突的信号；
- 当前材料不能判断的事项；
- 账号模式中取样可能带来的偏差。

### 6. 迁移与原创边界

列出可迁移的机制和不可复制的个体化特征。用户提供适配目标时，按 `references/adaptation-guide.md` 增加目标约束、机制映射、原创结构骨架和单变量验证计划。

不输出一比一模仿成稿、口头禅库或虚构用户体验。

### 7. 证据不足与补样建议

具体说明：

- 需要哪类主题、时间段或反例；
- 需要全文、视觉说明、用户有权分享的数据，还是时间上下文；
- 新材料将验证或推翻哪条低置信假设；
- 账号模式未覆盖的目录区间或未解析格式。

### 8. 下一轮验证

给出 1–3 个最小实验，每次只改变一个变量。使用“假设、变量、观察信号、停止条件”结构，不承诺结果。

### 9. 诚实边界

至少说明：

- 这是已成功读取材料的快照，不等于创作者真实人格或完整策略；
- `PUBLIC_SAMPLE` 不是全量账号；`ACCOUNT_PACKAGE` 只能覆盖当前提供的资料包；
- 未提供或未成功读取的信息没有被推断为事实；
- 相关性不等于平台因果；
- 输出不保证流量、审核、收益、法律或平台合规；
- 报告没有执行账号互动、外部写入或生成独立 Skill。

## 分模式输入审计

### `QUICK_SET`

| 项目 | 结果 |
| --- | --- |
| 输入模式 | `QUICK_SET` |
| 收到数量 | 原始输入总数 |
| 有效数量 | 可独立深析数 |
| 编号映射 | `N01`–`N08` 与原输入的对应关系 |
| 重复与降权 | 重复关系和处理 |
| 条件样本 | 广告、转载、离群或低信息项 |
| 安全处理 | 疑似注入、个人信息或敏感内容处理 |
| 缺失模态 | 未提供的视觉、互动、时间或后台信息 |

### `PUBLIC_SAMPLE`

| 项目 | 结果 |
| --- | --- |
| 输入模式 | `PUBLIC_SAMPLE` |
| 目标定位 | 用户提供的公开 URL 或唯一标识；输出时可最小化显示 |
| 盘点范围 | 实际读取的公开页面、时间范围和读取时间 |
| 发现/解析/全文/深析 | 四个客观计数 |
| 停止原因 | 页面末端、最多 60 个目录项、宿主上限或访问阻断 |
| 取样规则 | 置顶、最近、公开高互动、主题差异和反例配额的实际使用情况 |
| 证据映射 | `Nxx → Sxxx` |
| 未覆盖项 | 未读页面、无法打开的全文、视觉或数据缺口 |
| 安全处理 | 注入、个人信息、登录阻断和访问边界 |

### `ACCOUNT_PACKAGE`

| 项目 | 结果 |
| --- | --- |
| 输入模式 | `ACCOUNT_PACKAGE` |
| 材料范围 | 用户明确提供的文件、目录、导出或包；避免公开绝对路径 |
| 发现/解析/全文/深析 | 四个客观计数 |
| 重复/低信息/失败/跳过 | 分类计数和原因 |
| 时间范围 | 资料包内可验证的最早与最晚时间；不可见时写未知 |
| 取样规则 | 分层配额和例外 |
| 证据映射 | `Nxx → Sxxx`，可选 `Axx` 定义 |
| 处理上限与停止原因 | 是否达到 500 条、50 MiB、宿主上限或格式限制 |
| 完整性声明 | 只声称包内覆盖；若用户称为完整导出，注明未向平台独立验证 |
| 安全处理 | 注入、路径越界、符号链接、个人信息和未支持格式 |

## 表格字段

- 证据编号必须存在于输入审计或证据定义中。
- 支持证据和反对证据不能混写；使用 `支持：N01, N03；反例：N05`。
- 不用百分比表示主观置信度；覆盖率和用户提供的可计算指标除外。
- 不引用大段原文；优先简短转述。必要短引文必须标注 `Nxx`，跨语言时保留原文并可附简短翻译。
- 不显示已遮蔽的个人信息，也不在附录恢复。

## 质量门槛

交付必须同时满足：

1. 状态、模式、覆盖声明和输入审计在核心结论之前。
2. 审计覆盖实际发现的所有原始项目，没有静默截断或隐藏失败。
3. `PUBLIC_SAMPLE` 没有被包装成完整账号；`ACCOUNT_PACKAGE` 没有被包装成平台已验证的全量账号。
4. 账号模式的 `Nxx → Sxxx` 映射完整，取样规则可复核。
5. 中、高置信度内容机制的 `Nxx` 证据合规率为 100%。
6. 每条推断都有适用条件、限制或替代解释。
7. 没有虚构来源、互动、视觉、动机、算法因果或用户经历。
8. 反例不会被藏在摘要之外，可迁移规则是功能机制而不是人格复制。
9. `HOLD` 不会被包装成完整蒸馏。
10. 未读取用户未指定的本地路径，未使用登录态/Cookie，未绕过访问控制，未进行账号互动、持续监控或外部写入。
