# 蒸馏报告输出协议

完整报告必须遵循本协议。输入不满足 3–8 篇有效笔记门槛时，只输出 `HOLD` 输入审计和下一步，不伪装成完整报告。

## 目录

1. 状态定义
2. 证据与置信度
3. 必需结构
4. 表格字段
5. 质量门槛

## 状态定义

只使用以下状态：

- `PASS`：收到 3–8 篇同一创作者的可分析笔记，能够完成完整报告。
- `HOLD`：样本数量、归属、内容完整性或安全问题阻止完整蒸馏；列出准确原因和补救动作。

不要用“基本通过”“大概可用”等模糊状态。

## 证据与置信度

### 证据类型

- `观察`：输入中直接可见，可用简短转述和 `Nxx` 定位。
- `推断`：由多个观察归纳，必须说明替代解释或限制。
- `未知`：输入不能支持；不得补造。

### 独立证据

完全重复、高度近似、同稿多发或只替换少量词语的样本只计一个独立证据。广告稿、转载和离群项是否计入，取决于它是否真实支持当前机制，并须在审计中披露。

### 置信度门槛

设有效独立样本数为 `V`：

| 置信度 | 门槛 |
| --- | --- |
| 高 | 至少 `max(3, ceil(V / 2))` 篇独立笔记支持，且无未解释的实质反例 |
| 中 | 至少 2 篇独立笔记支持；存在的冲突已被限定为条件或例外 |
| 低 | 仅 1 篇支持、依赖较强推断、存在冲突，或样本信息有限 |

任何中、高置信度结论都必须列出全部支持的 `Nxx`。低置信度不能写成确定事实。

只允许使用表中的 `高`、`中`、`低` 三个值。不得创造“中高”“较高”“中低”、星级、百分比或数值分数来替代它们。

## 必需结构

### 1. 标题与状态

```markdown
# 创作者内容操作系统蒸馏报告

状态：PASS / HOLD
分析范围：仅基于用户提供的文本
```

状态与分析范围必须出现在任何摘要或核心结论之前。

### 2. 输入审计

使用表格列出：

| 项目 | 结果 |
| --- | --- |
| 收到数量 | 原始输入总数 |
| 有效数量 | 可独立分析数量 |
| 编号映射 | N01–N08 与原输入的对应关系 |
| 重复与降权 | 重复关系和处理 |
| 条件样本 | 广告、转载、离群或低信息项 |
| 安全处理 | 疑似注入、个人信息或敏感内容的最小化处理 |
| 缺失模态 | 未提供的视觉、互动、时间或后台信息 |

若为 `HOLD`，到此后只补充“阻塞原因、需要用户补充或缩减的内容、可做的有限观察”，不要继续输出完整五层结论。

### 3. 执行摘要

在 `PASS` 时列出 3–6 个最重要模式：

| 模式 | 类型 | 证据 | 置信度 | 一句话限制 |
| --- | --- | --- | --- | --- |
| 可执行的机制描述 | 观察 / 推断 | Nxx, Nxx | 高 / 中 / 低 | 适用条件或未知项 |

### 4. 五层内容操作系统

依序使用以下标题：

```markdown
## 一、定位层
## 二、选题层
## 三、结构层
## 四、表达层
## 五、运营层
```

每层使用结论表：

| 字段 | 内容 |
| --- | --- |
| 观察 | 文本直接呈现的模式 |
| 可迁移规则 | 情境、动作、作用 |
| 适用条件 | 规则成立的主题、受众或资源条件 |
| 反例或限制 | 冲突样本、替代解释、缺失信息 |
| 证据 | 全部支持和反对的 Nxx |
| 类型与置信度 | 观察 / 推断；高 / 中 / 低 |

一层可以有多条结论，但不要为了填满结构制造结论。证据不足时明确写“未知”。

### 5. 模式边界

分开列出：

- 稳定模式；
- 条件模式；
- 单次实验或离群项；
- 相互冲突的信号；
- 不能从当前文本判断的事项。

### 6. 迁移与原创边界

列出可迁移的机制和不可复制的个体化特征。用户提供适配目标时，按 `references/adaptation-guide.md` 增加：

- 目标约束；
- 机制映射；
- 原创结构骨架；
- 一次只改变一个变量的验证计划。

不要输出一比一模仿成稿、口头禅库或虚构用户体验。

### 7. 证据不足与补样建议

具体说明缺什么，而不是泛泛说“需要更多数据”：

- 需要哪类主题或反例；
- 需要文本、视觉说明、用户有权分享的数据，还是时间上下文；
- 新样本将验证或推翻哪条低置信假设。

### 8. 下一轮验证

给出 1–3 个最小实验，每次只改变一个变量。使用“假设、变量、观察信号、停止条件”结构，不承诺结果。

### 9. 诚实边界

至少说明：

- 这是有限文本样本的快照，不等于创作者真实人格或完整策略；
- 未提供的信息没有被推断为事实；
- 相关性不等于平台因果；
- 输出不保证流量、审核、收益或法律及平台合规；
- 报告没有执行外部动作，也没有生成独立 Skill。

## 表格字段规则

- 证据编号必须存在于输入审计中。
- 支持证据和反对证据不能混写；可分别标为 `支持：N01, N03；反例：N05`。
- 不用百分比表示主观置信度，除非用户提供了可计算数据和口径。
- 不引用大段原文；优先简短转述。必要短引文必须标注 `Nxx`。
- 不显示已遮蔽的个人信息，也不在附录重新恢复。

## 质量门槛

交付必须同时满足：

1. 输入审计覆盖所有原始项目，没有静默截断。
2. 中、高置信度结论的证据合规率为 100%。
3. 每条推断都有适用条件、限制或替代解释。
4. 没有虚构来源、互动、视觉、动机、算法因果或用户经历。
5. 反例不会被藏在摘要之外。
6. 可迁移规则是功能机制，不是同义改写或人格复制。
7. `HOLD` 不会被包装成完整蒸馏。
8. 当前版本不会读取文件、联网、抓取、登录、写外部系统或生成独立 Skill。
